3. OAuth success notification fires before connection actually loads — race condition
ConnectionsPage.tsx
When a platform OAuth completes, the handler immediately shows "Connected!" and calls loadConnections(). If loadConnections() fails or returns stale data, user thinks they're connected but the connection doesn't appear in the list.
❌ Current code
notify.success("Success", `${label} Connected!`);  // fires immediately
loadConnections();                                  // async, no await, no error handling
✅ Fix
try {
  await loadConnections();
  notify.success("Connected", `${label} connected successfully`);
} catch {
  notify.error("Error", `${label} connected but failed to refresh. Please reload.`);
}
Race ConditionFalse Positive

9. SchemaFieldSelector expanded groups don't update when fields change
SchemaFieldSelector.tsx
Uses an `initialized` boolean flag to prevent re-running the expand logic. But if fields prop changes after mount (e.g., user switches connections), the expanded group state is stale — wrong groups shown as expanded. 
useEffect(() => {
  if (fields.length > 0 && !initialized) {  // runs ONCE only
    setExpandedGroups(...);
    setInitialized(true);  // never re-runs even if fields change
  }
}, [fields, selectedIds, initialized]);

useEffect(() => {
  if (fields.length === 0) return;
  const selectedSet = new Set(selectedIds);
  const groupsToExpand = new Set(
    fields.filter(f => selectedSet.has(f.id)).map(f => f.group ?? 'General')
  );
  setExpandedGroups(groupsToExpand);
}, [fields]);  // Re-run when fields actually change
